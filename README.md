# NGA → DFCX E2E Automation with Ollama

Drives an NGA voice journey to the point where it hands off to Dialogflow CX,
asserts the handoff payload, and then lets **Ollama role-play the customer for
every turn after the steering utterance**.

```
session_start → wrapper/ident steps → steering utterance
                                            │
                                   transferToDialogflow
                                            │
                        ┌───────────────────▼───────────────────┐
                        │  autonomous loop (Ollama drives)      │
                        │  VA turn → Ollama customer reply → …  │
                        └───────────────────┬───────────────────┘
                                            │
                     ┌──────────────────────▼──────────────────────┐
                     │  the call is MULTI-LEG                      │
                     │  DFCX ──transferToNga──▶ NGA                │
                     │  NGA ──transferToDialogflow──▶ DFCX         │
                     │  …repeating as often as the agents ask…     │
                     └─────────────────────────────────────────────┘
```

**A handback is a transition, not an ending.** When DFCX returns control to
NGA the loop switches channel and keeps the same customer, the same goal and
the same transcript; if NGA steers the call back into DFCX, it switches back.
Ollama keeps answering whichever system is speaking. The conversation only
stops on a genuine end signal, a stop phrase, or a guard rail — never on a
handback. `--max-legs` (default 6) bounds the ping-pong.

## Setup

```powershell
uv sync
ollama pull qwen2.5:7b
```

> **Model choice matters.** `qwen2.5:0.5b` is too small for this task — it
> mirrors the VA's sentences back instead of playing the caller, and drifts out
> of French. Use a 7B-or-larger instruct model (`qwen2.5:7b`, `llama3.1:8b`,
> `mistral-nemo`). `health_check()` prints a warning for models ≤ 2B.

## Validate

```powershell
uv run python -m compileall -q .\automation .\orchestrate.py
uv run pytest -q
```

## Run

```powershell
# Live: real NGA + real DFCX + real Ollama
uv run python .\orchestrate.py e2e-handoff --env staging --tags billing --live

# Offline smoke test (scripted fake DFCX + canned customer, no Ollama needed)
uv run python .\orchestrate.py e2e-handoff --env staging --fake-llm

# Assert the handoff only, skip the conversation
uv run python .\orchestrate.py e2e-handoff --env staging --no-autonomous

uv run python .\orchestrate.py list-cases
```

### CLI flags

| Flag | Purpose |
|---|---|
| `--env` | Key from `config/environments.yaml` (default `staging`) |
| `--suite` | Case folder (default `suites/e2e_handoff`) |
| `--tags a b` | Run cases carrying **all** listed tags |
| `--name SUBSTR` | Run cases whose name contains `SUBSTR` |
| `--live` | Use the real NGA + DFCX stack (otherwise the offline fake) |
| `--autonomous` / `--no-autonomous` | Force the Ollama loop on/off, overriding the case |
| `--fake-llm` | Run the loop with canned replies — for CI without Ollama |
| `--model` / `--ollama-host` | Override `$OLLAMA_MODEL` / `$OLLAMA_HOST` |
| `--max-turns N` | Override `autonomous_flow.max_turns` for every case |
| `--max-legs N` | Override `autonomous_flow.max_legs` — how many NGA↔DFCX bounces a call may make (default 6) |
| `--max-attempts N` | Retries when the model echoes the VA (default 3) |
| `--seed N` | Ollama seed, for reproducible conversations |
| `--report PATH` | JSON report path (default `reports/e2e_handoff.json`) |

Exit code is `0` only when every case passes.

## Writing a case

Cases live in `suites/e2e_handoff/*.yaml` under an `evals:` list.

```yaml
evals:
  - name: "bill_promo_expired_nga_to_dfcx"
    tags: ["smoke", "e2e", "billing", "fr-ca"]
    session_start: {event: "session start", variables: {...}}
    wrapper_steps: [{kind: "dtmf", input: "157", label: "tester_id"}]
    identification_steps: [{kind: "text", input: "Oui", label: "service_confirmation"}]
    steering_utterance: "J'essaie de régler une offre promotionnelle qui est expirée."

    # Asserted against the transferToDialogflow payload.
    expected_transfer:
      environment: "projects/.../environments/..."
      route: "bill_promo_expired"
      language: "fr-ca"        # compared case-insensitively
      handoff_to: "post_steering"

    # Everything after the steering utterance is generated by Ollama.
    autonomous_flow:
      enabled: true
      max_turns: 8
      customer_goal: >          # required when enabled
        Understand why the promotion expired and whether an equivalent can apply.
      customer_profile: >
        Canadian French, brief and cooperative.
      stop_phrases: ["au revoir", "bonne journée", "merci d'avoir appelé"]

    # Assertions over the autonomous conversation (all keys optional).
    expected_conversation:
      min_turns: 2
      max_turns: 8
      must_mention: ["promotion"]            # case-insensitive, across all VA text
      must_not_mention: ["erreur système"]
      expect_stop_reason: "stop_phrase"      # prefix match
      forbid_stop_reasons: ["max_turns", "empty_llm_response", "no_va_text"]
      expect_end_reason: "end_interaction"   # end_interaction | conversation_success | live_agent_handoff
      require_empty_user_turns: false        # fail if Ollama ever returns ""

      # --- multi-leg (NGA <-> DFCX) assertions ---
      expect_legs: 3                         # contiguous stretches, incl. the first
      expect_handbacks: 1                    # DFCX -> NGA transfers
      expect_retransfers: 1                  # NGA -> DFCX transfers
      min_handbacks: 1                       # or a lower bound
      min_retransfers: 1
      expect_final_channel: "dfcx"           # which system ended the call
      expected_handback:                     # the LAST handback payload
        transferToNga: "projects/.../apps/nga-app-id"
        handoff_from: "bill_dispute_charge"  # looked up in `variables`
        handoff_to: "billing_menu"
      expected_handbacks:                    # or pin each one, in order
        - {handoff_to: "billing_menu"}
      expected_retransfer:                   # the LAST NGA -> DFCX transfer
        route: "tech_internet_outage"        # looked up in `parameters`
        handoff_to: "post_handback"
```

`expected_conversation` is only evaluated when the autonomous loop actually ran.

### Multi-leg calls (handback and back again)

A real call rarely stays in DFCX. DFCX can return control to NGA at any point
with a `transferToNga` custom payload, and NGA can steer it into DFCX again —
often onto a **different route** — as many times as the journey requires.

The loop models this as **legs**. Leg 1 is DFCX after the steering utterance;
every handback or retransfer starts a new leg. Ollama keeps playing the same
customer across all of them, with one continuous transcript, so the model
never loses the thread when the call changes hands.

Detection rules, in priority order on each turn:

1. **Transitions win.** A `transferToNga` on a DFCX turn is handled before the
   turn's `end_session` flag and before stop-phrase matching — DFCX almost
   always ends *its own* interaction and says goodbye while handing back, and
   neither means the call is over.
2. Payloads are read from the adapter's parsed `handback` / `transfer` field,
   falling back to scanning `raw` with `utils.extract_handback` /
   `extract_transfer`, so a thin live adapter still works.
3. A payload-only turn (no `response_text`) is a valid transition, never
   `no_va_text`, and costs no Ollama call.
4. Repeat detection is keyed **per channel**, so NGA and DFCX both saying
   "Comment puis-je vous aider?" is not a fallback loop.

`live_agent_handoff` is still terminal — it is a SIP deflection to a human,
not a return of control to NGA.

Per-case knob: `autonomous_flow.max_legs` (default 6). `max_turns` remains a
global ceiling across *all* legs, not per leg.

### Unresolved payload references (`$session.params.…`)

A DFCX custom payload is a **template**. The `Trigger NGA` route builds its
target from `$session.params.nga_agent_id`. When that parameter was never
bound in the session, DFCX does **not** error and does **not** emit null — it
passes the *literal string* through:

```jsonc
// healthy — real telephony, base62 session id
{ "transferToNga": "projects/gcp-it-prod-va-dlgflw/locations/us/apps/06199ff5-…",
  "variables": { "handoff_from": "nlu_steering", "handoff_to": "", … } }

// broken — the app id was never bound
{ "transferToNga": "$session.params.nga_agent_id",
  "variables": { "handoff_from": "nlu_steering", "handoff_to": "", … } }
```

Both payloads are structurally identical, so **the transfer still fires** and
every other assertion still passes — the caller just lands nowhere. That is
the "transfer works but the experience is wrong" failure.

The harness handles it in two places:

1. **Prevention.** `run_case` seeds `nga_agent_id` into the DFCX session on the
   inbound hop, exactly as a real NGA steering app does. Configured per
   environment with `nga_app_name` (defaults to `app_name`) and
   `nga_agent_id_param` (defaults to `nga_agent_id`). Look for `[SEED]` in the
   output.
2. **Detection.** Any `$session.params.*` left unsubstituted in a transfer
   payload is recorded on the `LegTransition` and **fails the case by
   default** — no opt-in needed, since it is always a defect. If a fallback app
   is configured the runner substitutes it and keeps driving the call (so the
   remaining assertions still mean something) while still failing; with no
   fallback the loop stops on `handback_unresolved_target`. Waive per case with
   `expected_conversation.allow_unresolved_references: true`.

> Note `handoff_to: ""` is **not** a defect — it is the documented "back to
> steering" value and is never reported.

Reproduce the broken payload offline: the `bill_dispute_charge` fake route
emits the template, and `FakeDfcxAdapter` substitutes it only when the
parameter is bound — so dropping `nga_app_name` from the environment
reproduces his exact payload.

### Re-entry after a handback (why it is an intent trigger, not text)

After DFCX hands a call back, the session is **parked on `Trigger NGA`** — a
page with no intent routes, only a Default-Welcome transition event and a
no-match handler. Sending the utterance there as text NO_MATCHes forever
(observed in prod at confidence `0.3` / `sys.no-match-default`).

A real client re-enters by **triggering the Default Welcome Intent**, with the
NGA parameters on the *same* request:

```jsonc
// the wire shape, taken from a prod capture
"queryInput":  { "intent": { "intent": ".../agents/<AGENT>/intents/00000000-0000-0000-0000-000000000000" },
                 "languageCode": "fr-CA" },
"queryParams": { "parameters": { "route": "...", "handoff_to": "post_steering", ... } }
```

That runs the real cascade — `Trigger NGA` → `Coming From NGA` →
`Post Steering Routing` → playbook — and leaves the session on a
conversational page again. Subsequent customer turns are ordinary text and
need no special handling.

`GoogleDfcxAdapter.reenter()` does this; `trigger_intent()` is the lower-level
call. Note the intent resource is **agent-scoped**, so it is built from the
agent portion of the environment path (`agent_of()`).

> An adapter without `reenter()` falls back to text and prints a
> `[RETRANSFER WARNING]`. That is the pre-0.6 behaviour and it strands the call.

**Detection.** `match_type` is now parsed from every turn. A run of
`NO_MATCH`/`NO_INPUT` responses stops the loop with `no_match_loop` and records
`stranded_page`. This is needed because **DFCX rotates its no-match prompts**,
so text-level repeat detection never catches a stranded session — in the live
run it burned 4 turns and 4 Ollama calls before `va_repeated` fired. Tune with
`autonomous_flow.max_consecutive_no_match` (default 2).

### Parameters the harness seeds

Real NGA puts two keys on the handoff that a harness-driven NGA session does
not send. Diffing a prod handoff payload against a captured run showed they
were the *only* two missing:

| parameter | why it matters |
|---|---|
| `nga_agent_id` | `Trigger NGA` builds `transferToNga` from `$session.params.nga_agent_id`. Unbound ⇒ DFCX emits the literal instead of an app. |
| `call_id` | Telephony-assigned; absent in SCRAPI sessions. Leaves `call_id`/`call_id_ref` as unresolved literals in session state. |

Configure per environment with `nga_app_name` / `nga_agent_id_param` and
`call_id` / `call_id_param`. When `call_id` is not set, a stable numeric id is
derived from the session id. Prod sends it as an **int** in the NGA payload but
as a **string** on the wire, so the harness seeds a string. Look for `[SEED]`
in the output.

### Assertions that are always on

Two outcomes are never legitimate, so they fail a case **even when it declares
no `expected_conversation` block** — otherwise a broken call reports a green
PASS, which is exactly how the NO_MATCH loop stayed invisible in a live run:

| defect | opt out with |
|---|---|
| unresolved `$session.params.*` in a transfer payload | `allow_unresolved_references: true` |
| session stranded on a NO_MATCH loop | `allow_no_match_loop: true` |

### Stop reasons

The loop ends with exactly one of:

| `stop_reason` | Meaning |
|---|---|
| `end_session:<field>` | The current system sent `end_interaction`, `conversation_success` or `live_agent_handoff` |
| `stop_phrase:<phrase>` | A configured stop phrase appeared in the VA text |
| `va_repeated` | The VA repeated the same turn on the same channel — a fallback loop |
| `max_turns` | Ran out of turns — usually a real failure |
| `max_legs` | NGA and DFCX bounced the call back and forth too many times |
| `handback_unresolved_target` | `transferToNga` was an unsubstituted `$session.params.…` literal and no fallback app was configured |
| `no_match_loop` | Consecutive `NO_MATCH` turns — the session is stranded on a page with no intent routes (see `stranded_page`) |
| `empty_llm_response` | Ollama returned nothing |
| `no_va_text` | The current system returned no speakable text |
| `handback_unsupported` | DFCX handed back but no NGA adapter was wired in |
| `disabled` | Autonomous mode was off |

An explicit end signal takes precedence over phrase matching — and a handback
takes precedence over both.

> `handback_to_nga` was a stop reason in 0.3.x. It no longer exists: a
> handback continues the call. Cases that asserted it should assert
> `expect_handbacks` / `expected_handback` instead, and it is worth adding it
> to `forbid_stop_reasons` to catch stale expectations.

## Why the model is the "assistant" in the chat transcript

The LLM **is the customer**, so `automation/adapters/llm_adapter.py` maps:

| Conversation turn | Chat role sent to Ollama |
|---|---|
| Virtual assistant | `user` |
| Customer (our model) | `assistant` |

Labelling the VA as `assistant` — the intuitive reading — makes the model
continue the VA's persona and parrot its last sentence back into DFCX. Chat
roles override any "you are the customer" system prompt. The runner therefore
keeps a speaker-neutral transcript (`{"speaker": "va"|"customer", "text": ...}`)
and the adapter owns the mapping. See `tests/test_regression_parroting.py`.

Each reply is additionally screened before it reaches DFCX:

- **echo detection** — rejected if it is ≥ 60 % similar to the VA turn, or
  lifts a 60-char verbatim span from it;
- **agent-phrasing detection** — rejected for tells like *"comment puis-je vous
  aider"* or *"je serai ravi de vous aider"*;
- rejected replies are **retried** (up to `--max-attempts`, default 3) with a
  corrective instruction and a slightly higher temperature. Discarded attempts
  are kept on `DynamicTestUser.rejected` for debugging.

## Offline mode

Without `--live`, `automation/adapters/fake_nga.py` plays the NGA legs and
`automation/adapters/fake_dfcx.py` replays a short scripted
French dialogue keyed by the case's `route`, so the whole pipeline — handoff,
Ollama loop, assertions, report — is exercised with no tenant and no creds.
**Adding a new route?** Add a script for it in `fake_dfcx.SCRIPTS`;
`tests/test_suite_files.py` fails if a case has no offline script.

A `fake_dfcx` script step carrying `handback` sends the call to
`fake_nga.FakeNgaAdapter`, which picks a script by the handback's
`variables.handoff_to`; a `fake_nga` step carrying `transfer` steers it back
into DFCX on the named `route`. `suites/e2e_handoff/bill_dispute_handback.yaml`
exercises the round trip (DFCX → NGA → DFCX) with no tenant and no Ollama:

```powershell
uv run python .\orchestrate.py e2e-handoff --env staging --fake-llm --name handback
```

## Report

`reports/e2e_handoff.json` contains a `summary` block plus, per case, the
journey trace, transfer payload, first/final turns, and the full
`autonomous_trace` (VA text + Ollama reply per turn, each tagged with its
`channel` and `leg`). `leg_transitions` lists every handback and retransfer
with its payload and the text spoken on the way out, and the `autonomous`
block carries `legs`, `final_channel`, `handbacks`, `retransfers`,
`dfcx_turns` and `nga_turns`. Sensitive parameters
(`clid_tmp`, `tfn`, `billing_account`, …) are redacted by
`automation/utils.py::SENSITIVE_KEYS`. The live CXaS trace is written to
`reports/cxas_raw_trace.jsonl`.
